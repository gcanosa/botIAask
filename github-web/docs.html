Overview

botIAask is an IRC bot written in Go. It connects with ergochat/irc-go, answers questions through an OpenAI-compatible endpoint (LM Studio by default) and can expose an optional web dashboard on port 3366. Everything is configured in a single YAML file and stored in per-feature SQLite databases under data/.

Requirements

  • Go 1.26 (see go.mod), only if you build from source.
  • An IRC network to connect to.
  • An OpenAI-compatible API: LM Studio, Ollama's OpenAI endpoint, or a hosted provider. Default: http://localhost:1234/v1.
  • Docker or Podman, only for the container route.

Installation

build from source
git clone https://github.com/gcanosa/botIAask.git
cd botIAask
cp config/config.yaml.template config/config.yaml
$EDITOR config/config.yaml
go build .              # produces ./botIAask
./botIAask
Config is required. The bot exits with an error if config/config.yaml is missing. There is no .env file; some API keys fall back to environment variables.

A minimal config to get talking:

config/config.yaml
irc:
  networks:
    - name: libera
      server: irc.libera.chat
      port: 6697
      use_ssl: true
      nickname: MyBot
      channels: ['#mychannel']
ai:
  lm_studio_url: http://localhost:1234/v1
  model: meta-Llama-3.1-8B-instruct

Daemon vs debug

The same binary runs in two ways. Pick one per environment.

🐞 Foreground / debug

  • Default when you run go run main.go or ./botIAask.
  • -debug (default true) prints verbose console output.
  • Stops with Ctrl-C. No PID file.
  • Best for setup, troubleshooting and containers (where the runtime supervises the process).

🛰️ Daemon

  • -daemon detaches; -dashboard implies daemon and enables the web UI.
  • Writes bot.pid (daemon.pid_file) and logs to logs/.
  • Control with -mode start|stop|restart.
  • Best for a VPS or home server without a supervisor.
shell
./botIAask -dashboard          # start daemon + web UI
./botIAask -mode restart       # restart it
./botIAask -mode stop          # stop it
./botIAask -rehash             # reload config without a restart
systemd tip: run the foreground form under a unit file (Restart=on-failure) instead of -daemon, and let systemd handle the PID.

Docker & Podman

The repo ships a multi-stage Dockerfile (static Go build, debian:bookworm-slim, non-root user bot, exposes 3366) and a docker-compose.yml. Both Docker and Podman work with the same files.

Compose

shell
mkdir -p state/config state/data
cp config/config.yaml.template state/config/config.yaml   # then edit it
docker compose up -d --build     # or: podman compose up -d
docker compose logs -f

Compose mounts state/{data,config,logs,pastes,upload_files} into /app/. Mount the directory config/ rather than the single file, so the runtime doesn't create a directory named config.yaml by mistake. Override with STATE_DIR, WEB_PORT and IMAGE environment variables.

Plain Podman

podman
./scripts/podman-build.sh                           # → botiaask:local
podman run -d --name botiaask -p 3366:3366 \
  -v ./state/config:/app/config:Z -v ./state/data:/app/data:Z \
  -v ./state/logs:/app/logs:Z botiaask:local

Prebuilt image

docker
docker run -d --name botiaask -p 3366:3366 \
  -v "$PWD/state/config:/app/config" -v "$PWD/state/data:/app/data" \
  berkelioar/botiaask:latest
Reaching LM Studio from a container: on Linux, use network_mode: "host" and http://127.0.0.1:1234/v1. On macOS/Windows use http://host.docker.internal:1234/v1 (Podman: host.containers.internal).

The container runs in the foreground, so use web.enabled: true in the config to serve the dashboard rather than -dashboard. Publishing a new image is covered by scripts/dockerhub-push.sh, push-latest.sh and push-version.sh.

Standalone binary

A single static file with no runtime dependencies (SQLite is pure Go, CGO_ENABLED=0). Cross-compile and copy it anywhere:

shell
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags="-s -w" -o botIAask .
scp botIAask config/config.yaml user@host:~/botiaask/

Run it from a directory that contains config/config.yaml; data/ and logs/ are created next to it on first run.

/etc/systemd/system/botiaask.service
[Unit]
Description=botIAask IRC bot
After=network-online.target

[Service]
WorkingDirectory=/opt/botiaask
ExecStart=/opt/botiaask/botIAask
ExecReload=/bin/kill -HUP $MAINPID
Restart=on-failure
User=bot

[Install]
WantedBy=multi-user.target

Live reload

Change config.yaml and reload without dropping the connection using any of: SIGHUP, ./botIAask -rehash, !rehash in IRC, or the dashboard's /api/rehash.

IRC commands

The prefix is ! by default. !help lists everything in IRC and botIAask -usage prints it on the command line.

GitHub tracker

Polls GET /repos/{owner}/{repo}/events and announces pushes, PRs, releases, issues (opened/closed) and branch/tag create/delete, with tags like [PUSH abcd123], [PR #42], [RELEASE v1.0]. Links are shortened with the RSS shortener.

irc
!gh add gcanosa/botIAask libera:#dev
!gh list
!gh search gcanosa/botIAask 42        # PR/issue number
!gh del gcanosa/botIAask

PublicNone needed (a public_repo classic PAT only raises the rate limit).

!gh add … --private only works in a PM over a connection the server confirms as TLS (numeric 671), and the PAT is intercepted before logging. Otherwise use the dashboard. Tokens are encrypted with AES-256-GCM using data/github_secret.key: back it up with data/.

Web dashboard

Enable with web.enabled: true (or -dashboard) and open http://localhost:3366. It includes live logs, Channel Stats, paste/upload moderation, feature toggles, bookmarks, market view, system stats and the GitHub tracker.

  • First login: if web.auth.password is empty, a random 32-char password is generated and printed once in the log.
  • Sessions: admin_session cookie (HttpOnly, Secure, SameSite=Strict, 24h).
  • CSRF: every mutating request needs X-CSRF-Token.
  • Login rate limit: 5 attempts / 15 min per IP.
  • Behind a reverse proxy: set web.trust_forwarded_for: true only if the proxy is trusted; put TLS in front of it.

Data & backups

Each subsystem owns a SQLite file in data/, created on first run. Scheduled hot backups (VACUUM INTO data/backups/) are on by default, every 24h, keeping 7 snapshots.

FileOwner
rss_seen.dbRSS dedup and news
stats.dbStats snapshots + per-channel daily rollups
bookmarks.dbBookmarks, tells, seen, reminders
uploads.dbPastes and file uploads
crypto.dbMarket history
prog_todos.dbProgrammer TODOs
web_auth.dbDashboard auth, sessions, CSRF
github_seen.dbGitHub event dedup, ETag cache

To back up manually, copy data/ (including github_secret.key) and config/config.yaml. Logs live in logs/<server>_<channel>_<date>.log with rotation.
